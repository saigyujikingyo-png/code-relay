# Code Relay 0.1.1 preview acceptance

Date: 14 September 2026. Shared rule baseline: **2026-09-14.1**.
Public output contract: **1.0**, unchanged from 0.1.0.

## Corrective scope

The release-commit CI for 0.1.0 exposed a failure in the Windows/Python 3.12
concurrent-claim test. The other five jobs passed. A bounded local stress run
then reproduced `PermissionError` at exclusive creation of `budget.lock` during
two simultaneous submissions. The precise operating-system cause is not
established. Earlier passing CI did not eliminate this intermittent defect.

Version 0.1.1 handles access denial within the same finite local lock-acquisition
retry as an existing lock. Persistent denial becomes the stable `budget_busy`
error with status/recovery guidance. No provider request is retried. Frozen
source checks, durable single-submission claims, quotas and review boundaries
are unchanged. New tests cover transient denial with exactly one dispatch and
persistent denial with no reservation, claim or dispatch. The original
concurrency test now includes useful failure diagnostics.

## Current local evidence

- Full suite: **106 tests in 10.199 s, 105 passed and 1 skipped**. The skip is
  unavailable creation of a test symlink; this is not a pass for that operation.
- Real stdio: seven output schemas discovered; actual status/error results and
  identical JSON text fallback validated.
- Eighteen focused output-contract tests remain part of the full suite.
- The original simultaneous-claim scenario passed **500 consecutive local
  iterations in 47.211 s** after the fix. This is bounded stress evidence,
  not a proof of every operating-system scheduling case.
- The standard-library runtime, two protocol adapters, graphical settings,
  bounded worker flow and privacy boundaries are described in the
  [previous receipt](2026-09-14-preview.md). Its historical test numbers and
  artifact hashes are not evidence for this patch's final package.

Public CI and package results are recorded below. Private host/account usage,
logs, installation and cloud-environment acceptance metadata are excluded from
this public receipt; they are retained only in the private development task.

## Acceptance boundary

Live ELM/OpenAI-compatible/Anthropic calls require user-supplied endpoints,
credentials and exact model IDs and remain unverified. The earlier real model
status call proves only that tool's callability; it also had an unrelated
read-only call contrary to the bounded prompt. No full coding-workflow,
representative Terra max benchmark, cost saving, fresh-device/removal or other
host acceptance is claimed. Source and Windows packages remain previews.
